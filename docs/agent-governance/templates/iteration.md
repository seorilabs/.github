# 재설계 UI 검수 <1/2/3/승인한 추가 회차>

새 화면·UI 개편(`test-plan.json`의 `redesign: true`, L3)에만 쓴다. 그 밖의 변경은 [실행 기록](run.md)을 쓴다.

## 실행 전 계획

- 설계 ID·조건 ID·후보 SHA·변경점:
- 계획 작성 시각·실행 순서·통과 기준:
- 구현자·다른 리뷰 에이전트·페르소나·필요 시 UX 전문가:
- 실제 환경·격리 계정·데이터·저장 경로:
- 핵심 기능 전체 목록:
- 이어받는 영향 없는 기반 기능(기능 ID·기준 SHA·실제 실행 시각·증거):

| 항목 | 기능 기대 결과 | UX 기대 결과 | 오류·복구 재현 | 남길 증거 |
|---|---|---|---|---|
| | | | | |

|---|---|---|---|---|
| | | | | |

## 수정·재확인·남은 문제

초기 발견과 수정·재확인 이력을 보존한다. 무제한 반복으로 회차 상한을 우회하지 않는다.

## 중단 원본 기록(실제로 중단된 v2 회차만)

- 원래 SHA,계획/시작/완료 시각과 failed 또는 blocked 판정:
- 원본 보고서 경로와 SHA256,실제 중단 사유:
- `interruption.actualScope.completed` 실제 완료 단위:
- `interruption.actualScope.incomplete` 실제 미완료 단위:
- `interruption.actualScope.notRun` 미실행 단위:
- 원본 bytes와 실제 범위를 대조한 근거:
- 후속 실제 재검수의 `resolutionEvidence`(아직 없으면 미해결):

완전 검수 수0회,승인 상한1회로 센다. 요구 범위의 기능 ID 선언을 실제 완료로 바꾸지 않는다. 원래 종료시각과 실패를 보존하며 추가 실행은 별도 사전 승인과 다음 실제 번호를 따른다. 실제 완전 검수 최소3회와 마지막 통과는 유지한다.

## 추가 진행 품의

3회 후 미완료면 문제·근거, 추가 회차·범위, 시간·비용, 검수자·환경, 중단 영향을 적고 **추가 회차 시작 전** 사람 승인 근거를 연결한다.

# UI7 한 회차와 첫 내부 TestFlight 검증 유지

상태: 승인 대기. 제품 후보는 PR #261·#262가 반영된 `89a4702d311e80b75de8bf11836e213ec9a7e94e`다. UI7 실행과 중앙 코드 변경은 아직 하지 않았다.

## 목적과 확인 근거

UI6는 `6a2c4fbf408c87658c78402a2b935ae99f9fa5f4`에서 빈 locale 저장을 읽다가 실제 Godot 오류6개로 실패했다. 독일어 준비 제목의 마지막 글자 줄바꿈도 관찰했다. #261은 빈 입력의 표준 SHA-256 처리를 유지하며 오류를 제거했고 #262는 실제 Label 측정254px에 맞춰 폭을240→258px로 고쳤다. 두 수정의 자동 회귀 통과는 전체 UI·실기기·E2E 통과가 아니다.

UI6 첫 실행2026-10-14T23:48:51.563513Z, 본180분 만료2026-10-15T02:48:51.563513Z, 총210분 만료03:18:51.563513Z를 그대로 보존한다. 이미 만료했으므로 재개하거나 재확인 시간을 새 본 검수에 쓰지 않는다. 602개 캡처와41/168 부분 관찰, 실제 오류6개·원본 로그 회전본·정상 Stop 확인과 환경 문제를 모두 보존하며 PASS로 바꾸지 않는다.

## 새 한 회차의 범위·검수자·시간

구현자와 다른 기존 검수자 `/root/ui_round6`가 새 UI7로 실행한다. 사용자 승인 전에는 복사·설계 준비만 가능하며 Run·입력·새 회차 시작은 금지한다. 승인 후 후보·설정·관찰 파일 차이와 로그 보존을 먼저 확인한다.

L3의28기능 전체와7언어×3크기×8패널168칸을 실제 Godot4.7.2 Editor 실행에서 확인한다. 최초 Run부터 본180분, 발견 문제를 고친 뒤 재확인 최대1회30분, 총210분이다. 잠금·오류·중단·캡처·판독·보고 시간도 포함한다. 추가 UI8·별도 반복·유료 도구 구매는 포함하지 않는다. 미완료·오류·원본 로그 누락은 실패 또는 미실행으로 기록한다. 추정85–110분은 예상일 뿐 상한을 늘리지 않는다.

빈 locale의 실제0바이트 원본을 실행 전에 복사·해시하고 지원/미지원 기기 언어와 저장된 선택 우선순위를 확인한다. 독일어 준비 제목의 실제 표시, 영웅이 실제 적을 향하는 방향과 타격 시점, 저장 보존·읽기 실패·재시도, 해금 후 재화·광고 실패 재시도 문구, 긴 화면 개인정보, FloatingText·흔들림 경계를 확인한다. 모든 동작·방향 애니메이션과 자연 전투·조건 fixture를 구분한다. headless나 개발용 광고 대체 구현을 실기기 Google SSV 통과로 표시하지 않는다.

## 증거와 실행 환경

기존 사용자 저장과 분리된 custom user dir, 크기별 QA project.godot와 관찰 helper를 선언하고 파일·해시·차이 manifest를 고정한다. 제품 GDScript·SDK·전투 수치·저장 식별자는 바꾸지 않는다. 각 재시작의 PID·최초 marker·시각·절대 로그 경로를 대응시키고 모든 회전본을 지속 보존한다. 실제 데이터와 원본 영상·상태·로그는 비공개, 보고서에는 제거한 요약·해시·위치만 기록한다. 새로운 전역 Godot 설정 변경이나 환경 복구 반복을 하지 않는다.

## 중앙 최소 보정과 한정 리뷰

기존 중앙 v1 예외에 approvedUiRounds=7을 추가하는 최소 보정만 한다. 별도 승인 원문·이 제안의 정확한 해시·최종 후보 SHA·실제 QA 설정 해시를 결속하고 UI6를 포함한 이전 회차의 원본 승인·소스·설정·실패·시간을 역사적 근거로 검증한다. 기존 UI4/5/6 승인을 새 SHA에 맞게 덮어쓰지 않는다. 잘못된 회차·승인·해시·순서·만료·누락 원본이 거부되는 회귀 검사를 포함한다.

새 중앙 PR의 최종 코드 diff만 Claude Code 읽기 전용으로 전송한다. 자격증명·PixelLab 원본·개인정보·실행 로그는 제외한다. 자동 Copilot을 포함해 총 리뷰 요청2회 상한, 수정 확인은 그 안에서만 한다. 승인 전 구현이나 전송하지 않는다.

## 출시 조건·순서와 만료

기존 글로벌 L3 설계와 테스트 계획을 유지한다. UI7 통과 뒤 같은 후보에서 최종 Editor 전체 E2E를 별도1회90분으로 계획·실행하고 시간과 증거를 겹쳐 세지 않는다. Android 기반4기능은 다른 에이전트의 같은 후보 실기기 검수와 실제 Test Ad·SSV 확정·정확한 지급·중복 방지까지 요구한다. 이 계획은 Android·iPhone 검수, 성능 비교, 전체 E2E, 서명·중앙 검증을 면제하지 않는다.

UI7→최종 Editor E2E→Android 필수 검수→정상 중앙 grant·버전 할당→기존 프로덕션 서명의 한 후보/한 빌드/한 업로드→실제 내부1.1.0 TestFlight 설치 순서다. 원래 만료2026-10-20T23:16:52.580641Z와 v1 종료2026-10-22T00:00Z를 연장하지 않는다. Cloud 산출물이 잘못된 profile·인증서면 한 빌드 실패로 기록하고 재시도하지 않는다.

첫 내부 완료 뒤 development_evidence.sh의 예외 인자를 제거하고 새로운1.1.1 후보에서 v2·L3·양대 실기기 전체 회귀와 E2E, 정상 중앙 검증, 심사·글로벌 공개·최종 국가 재조회·스토어 설치와 업데이트 실행을 수행한다. 중국 본토·베트남·AppsInToss 제외를 유지한다. 실행 티켓은 #240이다.

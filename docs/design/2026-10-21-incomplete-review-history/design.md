# 불완전한 초기 UI 검수 이력 보존

승인 범위는 별빛 견습생의 [후속 변경안](https://github.com/seoleeapps/starlit-apprentice/blob/c69c8d4c7534dbf84a9a33b91b6c28ae65f4b952/docs/06-release/2026-10-21-launch-blockers.md)에 대한 사용자 대화의 “승인한다”다. [승인 기록](https://github.com/seoleeapps/starlit-apprentice/blob/495c3e4/docs/design/2026-10-21-rating-and-review-recovery/design.md)은 기존 실패와 결손을 보존하고 새 후보에서 최대3회 독립 검수하는 범위를 기록한다. 이 변경은 그 복구안을 사실대로 표현하는 하위호환 형식 보완이다. 제품 검수, 기기 검수와 출시 승인을 면제하지 않는다.

## 문제와 동작

현 v2는 모든 `reviewRounds`에 후보 SHA와 계획 시각을 요구하고 순번1부터만 받는다. 초기 두 회차가 dirty tree에서 실행돼 이 값이 없는 사례는 소급 조작하거나 회차 이름을 바꾸지 않고 표현할 수 없다. 단일 추가 회차 승인만으로 이 필수 필드가 면제되지 않는다.

선택 필드 `reviewHistoryRecovery`에 reason과 기존 최초3회의 attempts를 넣는다. 실제 알 수 없는 sourceSha, plannedAt, startedAt는 명시null이며 completedAt, 실제 판정, 원본 보고서 해시와 보존 증거는 필수다. 알려진 시각은 유효한 달력 날짜와 순서를 검사한다. 실패/차단 판정은 해결 근거를 유지한다. 해시는 보존 원본을 식별하는 선언이며 verifier가 임의URL에서 원본 bytes를 조회해 진위를 보증하지는 않는다. 실행자는 evidence 생성 시 실제 원본/판정/해시를 독립 대조해야 한다.

과거3회는 승인 상한의 회차 수에는 포함하지만 합격 회차 수에는0회로 계산한다. 기존 회차를 잘라내거나 4회를 이력에 넣을 수 없다. 새 `reviewRounds`는 번호4부터 시작하고 완전한 독립 검수 최소3회가 필요하다. 새 회차의 기능과 UX는 전체 기능 목록을 각각 덮고 모두 현재 후보 SHA와168시간 안의 근거여야 한다. 과거3회의 마지막 실행 완료 이후, 각 새 계획 이전에 받은 추가 회차 승인이 상한을 덮어야 한다. 마지막 회차 통과와 이전 실패 해결, L3 실행, CI 확인, 플랫폼 하한과 출시 범위 검사는 유지한다.

기존 정상 v2와 v1 입력은 바뀌지 않는다. v1에 새 복구 필드는 허용하지 않는다. 이 형식은 UI 재설계에만 사용한다. CLI/환경변수 bypass와 저장소 전용 grant를 만들지 않는다. 기존 schemaVersion2의 선택 필드 추가다.

## 검증과 운영

기존 schema 거부를 먼저 재현했다. 새 경로의 유효 사례와 회차 잘라내기, 재번호, 비핵심 기능 누락, 두 회차만 실행, 독립성/후보/168시간/시각/승인 상한 위반을 차단하는 테스트를 추가한다. 정상 전체 계약 테스트와 package 검사, actionlint를 실행한다. 중앙 저장소 PR 필수 검사와 로컬 모델 리뷰를 거친 뒤 main에 반영한다. 필드 없는 소비자는 동작이 같고 이 필드를 쓰는 소비자는 중앙 반영 전 schema에서 차단된다.

UI1/2의 결손은 이 PR의 제품 실행 증거가 아니다. 중앙 서비스 계약 테스트에는 합성 fixture만 쓰고 실제 제품 QA로 게시하지 않는다. 적용 후 별빛 견습생은 새 회차를 실제로 계획/실행/기록한 뒤 정상 게이트를 다시 실행해야 한다.

## 목적과 흐름

현재 v2는 현재 후보의 부분 중단을 `interruption`으로 보존하지만 새 후보에서 그 기록을 과거로 옮길 필드가 없다. 완전 과거 회차에 중단을 넣거나, 부분 실패를 완료로 바꾸거나, 실제 순번을 다시 매기지 않는다. 제품 UI 변경은 없고 계약 소비자의 흐름은 원본 보존, 형식 검증, 합친 실제 순서 확인, 새 후보의 완전한 독립 검수 확인 순서다.

`reviewHistoryRecovery.interruptedRounds`를 선택 배열로 추가한다. 항목은 기존 과거 완전 회차와 같은 `round`, 당시 `implementer`, `originalReportSha256`, `evidence`를 갖고 `round.interruption`이 필수다. 알려진 SHA와 계획, 시작 및 완료 시각은 null로 바꾸지 않는다. 원래 기능과 UX의 failed 또는 blocked, 중단 사유와 completed/incomplete/notRun 범위, 원본 해시와 독립 검수자를 보존한다. 바깥 원본 해시와 중단 안의 원본 해시는 같아야 한다. 원본 bytes, 실제 판정과 해시 및 후속 해결은 실행자가 별도 대조한다. 검증기는 임의 증거 URL을 가져와 인증하지 않는다.

각 배열은 원래 번호 순으로 기록하며 완전 과거와 중단 과거를 합쳐 초기 결손3회 이후 연속 번호와 시간 순서를 확인한다. 중복, 누락, 서로 겹치는 실행, 당시 구현자와 검수자의 동일인, 원래 계획 뒤의 승인과 부족한 상한을 거절한다. 최초 결손3회의 기존 null과 원본 판정은 유지한다. 중단은 완전 과거 회차에 넣을 수 없다.

과거 중단 회차는 다른 과거 회차처럼 현재 완전 검수 수에0회이고 실제 순서와 승인 상한에는1회다. 예를 들어 결손1~3, 완전4~9, 중단10과 완전 실패11을 보존하면 현재 회차는12부터 시작한다. 새 후보에서 완전한 독립 전체 기능 검수 최소3회와 마지막 기능/UX 통과, 모든 실패의 실제 후속 해결이 필요하다. 새 승인은 과거 마지막 완료 이후이면서 각 새 계획 이전이고 실제 번호 상한을 덮어야 한다. 현재 회차의 정확한 후보 SHA,168시간,사전 계획,독립성과 전체 기능, 실행과 플랫폼 및 출시 하한은 바꾸지 않는다. 원래 승인 시각과 한도는 개별 승인 객체로 보존한다.

## 구조와 호환성

선택 evidence 필드와 정책 선언, 검증기의 기존 과거 검사 및 현재 회차 offset만 확장한다. 기존 중단 판정과 부분 범위 검사는 재사용하며 과거 기능 ID를 현재 목록으로 덮어 검사하지 않는다. 정상 v2의 기존 배열 순서와 검증 결과, 현재 중단의0회 처리와 v1의 기존 수명 및 입력 계약을 유지한다. 앱 이름, 특정 SHA 또는 특정 최대 회차의 예외를 추가하지 않는다. 앱 실행, 폰트 수정, 기기와 마켓 변경은 범위 밖이다.

## 원래 실행과 실패

최초 3회에서 각각 25개 기능의 입력과 상태 및 저장 검사를 실행했다. 그러나 1, 2회차는 전체 화면의 시각 검토를 종료 보고 뒤에 처음 수행해 UI 검수가 제때 완료됐다는 근거가 부족하다. 1회차 보고서 작성 시각 `06:41:19.197653Z`는 2회차 계획 `06:41:19.194181Z`보다도 늦다. 1회차 전체 화면 첫 열람은 `06:47:20.848Z`, 2회차는 `06:47:11Z`였다. 이 시각은 2026-10-23 UTC다.

원래 passed 보고서를 보존하고 별도 정정 기록에서 1, 2회차 UX 완료를 인정하지 않는다. 첫 중앙 검사의 `ROUND_OVERLAP`와 정정 근거의 `UNRESOLVED_REVIEW`도 보존한다. 이미 수행한 최초 3회는 새로운 정상 검수 3회에 0회로 센다. 번호를 1로 다시 시작하지 않는다.

현재 `reviewHistoryRecovery.attempts`는 sourceSha, plannedAt 또는 startedAt의 실제 결손이 하나 이상 있어야 한다. 이번 기록은 모두 알려져 있어 null로 바꿀 수 없다. 기존 completedRounds와 interruptedRounds에도 맞지 않는다. 제품 실행을 더 해도 현재 중앙 계약으로 이 알려진 실패를 정직하게 이어서 표시할 수 없다.

## 제안하는 계약

개발 근거 schema에 선택 `invalidInitialReviewHistory`를 추가한다. 기존 reviewHistoryRecovery와 동시에 사용할 수 없다. 최초 정확히 3개의 원본 round, 구현자, 원본 보고서 SHA-256, 실제 시각과 후보, 원래 판정, 잘못된 판정의 정정 내용, 원본 및 정정 근거를 보존한다. 원본 시각의 겹침이나 잘못된 완료 판정을 없애거나 통과로 바꾸지 않는다. sourceSha와 알려진 시각은 null로 낮출 수 없다.

이 배열은 과거 실패를 표현하는 용도이며 통과에 0회를 부여한다. 새 검수는 번호 4, 5, 6으로 이어지고, 추가 승인 시각은 마지막 원본 실행 및 정정 완료 뒤이며 각 새 계획보다 앞서야 한다. 최소 3개의 새 완전 검수는 같은 현재 후보의 모든 기능을 독립 실행하고 기능과 UX를 모두 통과해야 한다. 새 회차는 서로 겹칠 수 없고, 계획과 실제 화면 검토 및 판정 보고서를 마친 다음 회차 계획을 작성한다. 최초 이력의 마지막 알려진 실행, 검토 및 정정 시각보다도 늦게 시작한다.

원본 hash와 정정 기록의 연결, 처음 3개 번호와 실제 source 및 시각, 사전 추가 승인, 현재 후보 결속과 전체 기능, 독립성 및 168시간을 검증한다. 잘못된 초기 이력의 예외를 현재 회차나 마켓 및 플랫폼 조건에 전파하지 않는다. 기존 ui/service, 정상 UI3, 결손 이력 복구 및 별도 과거 예외의 결과는 유지한다.

중앙 구현 범위는 `contracts/development-evidence.schema.json`, `scripts/release/verify-development-evidence.mjs`, 관련 단위 테스트와 실행 문서다. 제품 코드는 바꾸지 않는다. source를 바꿔야 하는 제품 결함이 새로 나오면 그 후보의 근거와 승인 범위를 다시 확인한다.

## 인수조건과 테스트

1. 알려진 시각과 실패를 그대로 가진 최초 3개와 승인 뒤 실행한 정상 4, 5, 6만 통과한다. 원본은 0회로 센다.
2. 원본 2개 또는 4개, 번호 초기화, 알려진 값의 null 변경, 원본과 정정 연결 불일치, 미해결 정정, 승인 전 추가 회차, 겹친 새 회차, 현재 후보 불일치, 기능 누락과 자기 검수는 실패한다.
3. 새 3개가 있어도 현재 회차의 실패와 미실행, 기한 초과, 플랫폼 및 출시 범위 위반은 차단한다.
4. 기존 중앙 전체 테스트 결과를 유지한다. TDD로 현재 fixture의 실패를 먼저 보존한다.
5. 중앙 보완 PR이 정식 리뷰와 CI를 통과해 병합된 뒤에만 제품 4회차를 시작한다. 6회까지 모두 통과하고 중앙 검사 3개를 통과한 뒤 같은 후보의 AIT 로컬 빌드, 호환 검사, PR 병합으로 진행한다.

## 추가 검수 승인 요청

- 범위: 고정 `76de041`의 25개 기능 전체를 매 회차 실제 개발 런타임에서 입력하고, 실행 중 각 기능 화면과 오류 및 복구를 직접 확인하는 독립 4, 5, 6회. 한국어, 영어, 긴 번역, 작은 화면과 200% 글자, 실제 저장, 광고 및 시트 연결과 SDK 이력 경계를 포함한다.
- 검수자: 구현자와 다른 독립 에이전트. 매 회차 새 소유 브라우저, 저장 namespace와 시계를 사용한다. 필수 이미지 목록과 실제 열람 시각을 보고서에 남기고 보고서를 닫은 뒤 다음 계획을 작성한다.
- 예상 시간: 중앙 구현과 전체 검증 및 리뷰 30~45분, 제품 3회 25~35분, 중앙과 빌드 및 PR 검사 10~15분. 총 65~95분 예상이며 실패에 따른 추가 회차나 범위 확대는 포함하지 않는다.
- 비용과 자원: 기존 로컬 개발 환경과 MiniMax 리뷰 예산, 기존 GitHub 정적 CI만 사용한다. 새 유료 서비스와 과금 설정 변경은 없다. 정확히 3회만 추가하고 7회차는 승인하지 않는다.
- 제외: 배포, 업로드, 심사, 운영 정책과 설정, 실제 기기. 기존 사전 빌드 산출물과 순서 위반은 보존하고 최종 빌드 근거로 세지 않는다.
- 중단 영향: 승인 전 #512의 코드 병합과 정식 빌드는 보류한다. 다른 승인된 Happy Farm 작업은 진행한다.

이 문서의 정확한 커밋과 중앙 test-plan 및 기존 제품 계획에 대한 추가 3회 승인을 함께 받는다. 승인 전 중앙 코드와 schema를 수정하거나 추가 제품 회차를 실행하지 않는다.

03

각 회차를 계획하고, 실제 실행으로 검수

검수는 작성자와 다른 리뷰 에이전트 · 필요한 경우 UX 전문 역할 추가

회차기능 검수UX 검수·페르소나
1회 · 기본 동작핵심 기능 전체의 인수조건·상태·입력·결과·저장다음 행동과 결과를 이해하는가
요구사항 검수자 + 처음 사용하는 사용자
2회 · 사용·복구핵심 기능 재실행 · 오류·취소·연속 입력·복구탐색·피드백·작은 화면·큰 글자·키보드·접근성
사용자 관점 검수자 + 필요 시 UX 전문가
3회 · 연결·회귀핵심 기능과 기존 기능 연결 · 재시작·저장 복구처음부터 끝까지 자연스럽게 완료하는가
회귀·복구 검수자 + 반복 사용자

회차 시작 전 기록

후보·핵심 기능 목록·검수 항목·기대 결과·순서·환경·검수자·격리 데이터·증거 계획을 작성합니다. 실행 후 계획을 소급 작성하거나 역할 전환을 독립 검수로 세지 않습니다.

3회 뒤 끝나지 않으면 품의

남은 문제와 근거, 추가 회차·범위, 시간·비용, 필요한 검수자·환경, 중단 영향을 보여줍니다. 승인 전 4회차를 시작하지 않습니다.

04

빌드 전과 배포 전, 전체 기능을 연결해서 실행

E2E: 사용자의 작업을 시작부터 완료까지 실제 실행해 확인

시작이번 변경 + 기존 구현 기능 전체저장·화면 전환오류·복구종료·재실행결과 기록

각 실행 직전에 수행

배포용 빌드를 시작하기 직전, 이미 만든 산출물을 배포하기 직전에 각각 개발 실행 환경 E2E를 수행합니다. 결과에는 최종 SHA·설정·환경·시나리오·증거를 연결합니다.

변경되면 다시 확인

E2E 뒤 코드·에셋·설정·의존성이 바뀌면 결과를 무효화합니다. 필수 항목을 실행할 수 없으면 확인 단계를 통과한 것으로 표시하지 않습니다.

제품개발 실행 환경별도 확인
게임Godot·Unity Editor Play/Run격리 저장 경로 · 실제 조작·실행 로그
웹개발 서버 + 실제 브라우저격리 계정·데이터 · 조작·상태·오류 경로
네이티브 앱개발용 실행 + 에뮬레이터 또는 실기기플랫폼 구매·광고·권한은 해당 기기 증거
API·서비스개발 실행 환경의 API·서비스 E2E실제 요청·상태·복구 결과

3회 기능·UX 검수와 최종 E2E는 별도 단계입니다. Editor 검수는 서명 산출물 검사·마켓별 실기기 QA·문구 검수·심사·공개 확인과 함께 적용합니다.

05

승인 설계에서 티켓·PR·검수까지 연결

확정한 선택: docs/design 정본 + Wiki 목록·요약·티켓 링크

Wiki에는 순서와 요약

날짜·승인 순서로 설계를 쌓고, 최신 원본과 승인 커밋을 따로 연결합니다. 기존 접수 이슈가 실행 티켓으로 충분하면 새 이슈를 중복 생성하지 않습니다.

자율 구현은 승인 설계부터

설계 없는 항목은 초안을 만들고 사람 검토를 기다립니다. 승인된 작업만 구현 큐에 넣고, 승인 대기 항목을 기록한 뒤 다른 적격 작업을 순차 처리합니다.

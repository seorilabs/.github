# Lizard Tycoon 1.9.0 과거 회차 범위의 승인 예외

사용자가 현재 후보의 과거 누락을 넘기고 빌드로 진행하도록 승인했다. 원문은 private 실행 티켓의 [승인 기록](https://github.com/seorilabs/lizard-tycoon/issues/805#issuecomment-6260553208)에 보존한다. 중앙 [실행 티켓](https://github.com/seorilabs/.github/issues/279)과 구현 기준 `2de4c3cc108a6063d0484e2910b66c6e253b651c`를 사용한다.

승인 범위는 후보 `055aae4422610e279417f3f3a7d2b9007cb1754d`의 `FEATURE_COVERAGE ux-1`, `functional-4`, `ux-4` 세 오류다. 같은 후보의 CI 113개와 68기능, Editor 8개 검사와 214단계, 원본 28장과 핵심 21기능을 확인했다. 과거 1차 UX의 핵심20/21과 중단된4차의 핵심5/21, 원래 실패와 현재 정상 검증의 failed 판정은 보존한다. 새 제품 화면이나 추가 UI 검수 회차는 없다.

## 구조와 제한

정상 v2 검증을 먼저 실행한다. 중앙에서 검토한 단일 grant의 저장소, 후보 SHA, 마켓별 실제 JSON 내용 해시, 태그와 단계, 승인과 만료 시각이 모두 맞고 정확히 세 오류만 남을 때 `human_exception` 결정을 반환한다. 마지막6차는 현재 후보의 기능과 UX가 통과해야 하며 과거 대상 회차는 해결 근거가 있어야 한다. 원래 검증 결과는 `originalVerdict`로 함께 반환한다.

| 조건 | 처리 |
|---|---|
| 승인한 후보와 원본, 과거 세 오류만 일치 | human_exception, 원래 failed 보존 |
| 다른 오류, 후보, 제품, 태그, 마켓 또는 자료 변경 | 원래 차단 유지 |
| 최종 회차 실패, 과거 해결 근거 누락 | 차단 |
| 승인 전 또는 만료 | 차단 |
| 일반 v2 또는 v1 | 기존 검증 유지 |

근거 해시는 JSON.parse 뒤 JSON.stringify한 UTF8의 SHA256이다. 공백 변경은 허용하지만 값이나 키 순서가 바뀌면 일치하지 않는다. 원문 bytes 해시는 보관본 대조용으로 보존하며 예외 판정은 파싱한 내용 해시를 사용한다. 앱의 근거와 제품 코드, 워크플로와 검증 CLI 입력은 변경하지 않는다. 생략용 환경변수와 새 CLI flag는 없다. 중앙 main에서 검토된 grant만 사용한다. 등록된 grant를 읽거나 파싱하지 못하면 오류를 표시하고 중단한다.

이번 승인은 빌드와 테스트 업로드까지만 적용한다. grant는 before-build와 before-deploy만 허용하고 before-release는 코드에서도 거절한다. 공개 배포에 해당하는 web과 service의 before-deploy에도 적용하지 않는다. 공개 승격과 심사 제출에는 정상 검증이 필요하다.

후보와 설계 승인, 실행자, CI 조회와 신선도, 최종 회차, 전체 기능, 플랫폼, 출시 범위와 산출물 검사는 유지한다. 정상 pass는 그대로 반환하고 예외일 때 CLI에 human_exception과 원래 세 오류를 출력한다.

## 테스트 계획

L1, 개발 환경의 중앙 Node 단위 검사와 CLI 실행이다. 실제 현재 근거의 정상 CLI가 세 오류로 차단되는 것을 선행 실패로 보존했다. 허용 사례와 저장소, 후보, 태그, 마켓, 단계, 내용, 승인 전, 만료, 추가 오류, 최종 실패와 과거 해결 근거 누락을 검사한다. 전체 npm test, pack:check와 git diff --check를 실행하고 실제 앱의 세 마켓 CLI도 같은 원본으로 확인한다.

제품 실행이나 기기 검수를 새로 했다고 기록하지 않는다. 릴리스 검증 로직의 교차 리뷰와 필수 CI를 완료한다. 실제 마켓 빌드와 테스트 채널 업로드는 중앙 변경이 반영된 뒤 앱에서 별도 실행한다.

## 운영과 제거

최대 기한은 현재 CI의 168시간 끝인 `2026-10-26T03:59:05Z`다. 만료나 원문 및 후보 변경은 중단한다. 이후 단일 grant를 제거하고 다른 제품의 상시 예외로 확장하지 않는다.

철회는 중앙 grant를 제거해 새 중앙 검증 실행부터 적용한다. 이미 시작한 마켓 작업은 별도로 취소해야 하며 즉시 철회 조회 기능이 있다고 주장하지 않는다. 기존 국가와 가격, 자격증명과 서명, 플랫폼 SDK 계약은 면제하지 않는다.

# Spiritgate Defenders 1.1.0 iOS 내부 TestFlight 선행 검수 예외 제안

## 결론과 확인 사실

사용자는 개발용 bundle/profile 생성을 금지했고 기존 프로덕션 프로필 사용과 기기 앱 삭제·덮어쓰기를 승인했다. Apple API로 기존 프로필 21개를 조회한 결과, 제품에 대응하는 프로필은 `BSCHL63LDG`의 `IOS_APP_STORE` 한 개다. 이 프로필에는 기기 목록이 없으며 연결된 iPhone의 USB 설치 권한이 없다. 프로필·bundle·인증서를 만들거나 바꾸지 않는다.

현재 최종 제품 소스는 `a745cec0d86d7b13e68d0174da14d8d188c44a89`다. PR #246은 병합됐다. 독립 UI 3차는 실제 Editor Run으로 진행 중이며, 별도의 최종 E2E와 Android 실기기 검사도 아직 완료되지 않았다. 미실행 결과는 통과로 표시하지 않는다.

## 요청하는 변경

기존 프로덕션 프로필을 유지하는 상태에서 **처음 한 번의 iOS 내부 TestFlight 빌드·업로드에 한해서**, iPhone에서만 확인할 수 있는 기반 기능 검수 시점을 업로드 후로 옮기는 중앙 예외를 검토한다. 이는 검수 면제가 아니며 App Review 제출·공개 국가 확대·공개 배포를 허가하는 예외가 아니다.

- 대상: `seorilabs/spiritgate-defenders`, App Store Connect `6792205995`, bundle `com.seorilabs.spiritgatedefenders`, 버전 `1.1.0`, 기존 Xcode Cloud `App Store Tag Archive`.
- 범위: 같은 제품 tree를 유지하는 후보 1개, 내부 TestFlight 검수 준비 1개, 최대 168시간. 후보 SHA·실제 설정 지문·공식 릴리스 번호를 중앙 원장으로 결속한다.
- 전제: 현재 3차 UI에서 비네이티브 제품 기능·UX가 실제 통과하고, 별도의 최종 Editor E2E가 전체 구현 기능을 실제 실행하며, Android의 영향받은 기반 기능 실기기 검수를 수행한다. 각 판정·미실행 항목을 그대로 보존한다.
- 허용될 경우: 중앙의 승인 예외 등록과 보호된 소비자 연결부를 Ready PR·필수 검사·읽기 전용 교차 리뷰로 반영한 뒤, 기존 프로덕션 서명과 공식 번호로 Xcode Cloud archive/upload를 한 번 수행한다. 배포 관련 변경 diff만 리뷰에 전송하고 자격증명·개인정보·PixelLab 원본 응답·실행 로그를 제외한다. 신규 PR별 리뷰 요청은 최대 2회다.
- 내부 설치 후: 실제 iPhone에서 새 설치·업데이트·오프라인·복귀·동의 허용/거절·SDK 신원 유지/경쟁·보상 광고와 SSV/중복 방지·실패 후 재시도·모든 제품 기능·성능을 검수한다.
- 중단: archive/서명/검증/업로드 실패는 원인을 기록하고 같은 작업을 무작정 반복하지 않는다. 새 후보나 설정 변경은 예외를 이어받지 않는다. 미실행 네이티브 검수를 실제 PASS로 바꾸지 않는다.
- 공개 조건: 실제 iPhone 검수와 전체 E2E가 통과하고 중앙 정상 검증을 다시 통과하기 전에는 심사 제출과 공개를 진행하지 않는다. 중앙 예외 설계가 이 제약을 기계적으로 강제하지 못하면 구현하지 않는다.

## 변경 대상과 위험

중앙 `seorilabs/.github`의 승인 예외 등록·검증과 제품의 Xcode Cloud 연결부에 한정한다. 전투 규칙·재화·저장 식별자·SDK 원본·아트는 바꾸지 않는다. 최소 연결 변경으로 새 source SHA가 생기면 원래 제품 tree·UI/E2E 관측을 보존하고 변경의 영향과 새 후보 결속을 검증한다. 검수 통과 후보와 공개 후보를 조용히 혼용하지 않는다.

위험은 iOS 장비 검수 전 내부 binary를 생성·업로드한다는 점이다. 내부 대상만 허용하고, 미검수 결과를 보존하며, 심사·공개를 차단해 범위를 제한한다. 개발 프로필 생성과 검수 조건 생략은 이 제안에 포함하지 않는다.

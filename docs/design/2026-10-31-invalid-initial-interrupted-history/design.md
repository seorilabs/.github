- 상태: 제안. 중앙 코드와 스키마 구현 전 검토가 필요하다.
- 중앙 기준: `78b29608d008ec28171a1ef5bb4efc905e030231`
- 제품 후보: Salt & Compass `4004d0daf3451020d941d59db3de05e0fc718dd6`
- 제품 요청: Google Play 알파 테스트. 공개와 다른 마켓은 범위 밖이다.

## 관찰된 이력

최초 독립 검수 1~3의 계획은 1회 시작 전에 함께 작성됐다. 1회는 UX 실패, 2회와 3회는 수정 후 통과했다. 기존 보고서, 후보 SHA, 실제 시각과 화면 근거는 NAS에 보존돼 있다. 검증기는 각 회차 계획이 전 회차 완료 이후여야 하므로 이 최초 기록을 정정해야 한다.

사용자는 추가 4~6회차를 승인했다. 4회는 2026-10-31 00:47:17 UTC에 계획하고 00:47:18에 시작했으나 최초 이력의 계획 순서 문제를 뒤늦게 발견해 00:48:32에 중단했다. headless는 통과했지만 렌더 실행은 부분 완료와 실패를 남겼고 화면 검토는 하지 않았다. 전체 기능과 UX는 blocked다. 원본 `alpha-preparation/round-4/report.md`와 해시를 그대로 보존한다.

최초 이력을 지금 정정하면 정정 시각은 4회 계획 이후다. 현재 `invalidInitialReviewHistory`는 정정 전 중단된 추가 회차를 별도 과거 배열로 받을 수 없고 `reviewHistoryRecovery`와 동시에 사용할 수 없다. 실제 실행 순서와 당시 승인 시각을 유지한 합성 검사에서 `EXTRA_ROUND_APPROVAL_REQUIRED`가 발생했다. 승인 시각을 고치거나 4회를 숨기지 않는다.

## 제안

`invalidInitialReviewHistory`에 선택 배열 `interruptedBeforeCorrection`을 추가한다. 각 원소는 원래 번호, SHA, 계획·시작·중단 시각, 독립 검수자, 기능·UX blocked/failed 판정, 실제 완료·미완료·미실행 범위, 원본 보고서 해시와 당시 사전 승인 증거를 보존한다. 최초 세 회차 종료 이후에 시작한 번호만 순서대로 허용하고, 원래 추가 승인이 해당 계획 이전이며 당시 허용 회차 수를 덮는지 검증한다. 정정 시각을 과거로 바꾸지 않는다.

이 기록은 통과 회차에 포함하지 않는다. 실제 마지막 중단과 최초 이력 정정이 모두 끝난 이후 새 승인을 받고, 다음 번호부터 현재 후보 전체 기능을 대상으로 독립 검수 3회를 다시 시행한다. 세 회차 모두 기능과 UX가 통과해야 한다. 현재 사례는 새 5~7회차가 필요하며 기존 4~6 승인으로 7회차를 대신하지 않는다. 원본 실패는 후속 확인 근거와 연결한다.

기존 `reviewHistoryRecovery`와의 동시 사용 금지, 최초 이력 3개 규칙, 원본 SHA·시간·해시, 독립성, 새 계획 간 순서, 168시간, 마켓과 플랫폼 조건은 유지한다. 임의의 중단을 소급 승인하거나 실제 새 검수 없이 제품 배포를 허용하지 않는다.

## 구현과 검증 범위

중앙 `contracts/development-evidence.schema.json`, `scripts/release/verify-development-evidence.mjs`, 해당 테스트, 개발 계약 및 실행 문서를 수정한다. 정상 UI 검수와 기존 이력 복구는 호환성을 유지한다. 먼저 현재 계약에서 실패하는 재현 테스트를 보존한다. 사전 승인 누락 또는 승인 한도 부족, 번호 중복·역전, 시작 전 중단, 정정 뒤 회차를 과거로 위장, 원본 해시 불일치, 자기 검수, 누락된 실제 범위, 새 회차 누락, 시각·후보 불일치와 기존 회귀를 거절한다. 중앙 테스트 계획은 별도 `test-plan.json`이다.

중앙 PR의 검사와 병합 후 제품 후보의 5~7회차 전체 검수와 기존 빌드·업로드 검증을 실행한다. 제품 코드와 결제·계정 설정은 바꾸지 않는다. 제품 실제 승인 시각과 범위가 계획보다 뒤거나 작으면 별도 승인을 받고, 실기기에는 접근하지 않는다.

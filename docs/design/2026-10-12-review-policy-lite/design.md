# 리뷰 기본값과 저장소 예외 정렬

- 설계 ID·버전: `2026-10-12-review-policy-lite`, v1
- 상태: 승인된 대화 범위의 실행 명세
- 승인 근거: 2026-10-12 대화의 “제안대로 지침 갱신하자. 세 저장소도 보안·결제·데이터·릴리스 변경은 리뷰 대상에 포함하고, 중앙 계약과 로컬 지침을 함께 맞춰줘.” 및 기본값 Lite 확인.
- 원본: 이 문서의 최초 커밋. 연결 티켓·PR은 PR 본문에 기록한다.

## 범위와 결정

| 변경 | 리뷰 요청 |
|---|---|
| 문서·주석·번역·에셋·자동 생성물·릴리스 문구와 버전 메타데이터만 변경 | 생략 |
| Backoffice·Official·`.github`의 일반 코드·설정 변경 | 생략 |
| 모든 저장소의 보안·결제·데이터 형식과 무결성·릴리스 실행 로직 변경 | 교차 리뷰 |
| 그 밖의 500줄 이상 코드 변경 | 교차 리뷰 |
| 그 밖의 코드·설정 로직 변경 | Copilot Lite |
| 교차 리뷰 불가 또는 해당 리뷰어의 사용 한도 소진 | 사유 기록 후 Copilot Balanced. 보안 민감 변경은 사람이 병합 결정 |

중앙 `contracts/review-policy.yaml`이 요청 대상과 예외, 깊이, 실패 처리를 소유한다. 실행 문서와 `~/.agent`의 개발 지침·PR 스킬을 함께 맞춘다. 리뷰 결과가 사람의 승인으로 계산되지 않는 것과 해당 변경의 리뷰 요청 의무를 구분한다. 기존 필드의 의미는 유지하고 `optional` 값을 필수 요청에 맞게 변경하며, 조건과 예외는 필드를 추가해 표현한다.

월간 사용량 소진·일시적인 요청 제한·분류하지 못한 한도 오류를 구분한다. 공급자가 제시한 재시도 시각을 존중하고, 실패·대체·재시도를 포함한 PR당 최대 2회는 유지한다. 초기화 시각을 추정하지 않으며 추가 과금·계정 설정을 변경하지 않는다.

## 인수조건과 검증

- AC-1: 기본 Lite와 교차 리뷰 대체 Balanced가 중앙 계약과 실행 지침에서 일치한다.
- AC-2: 세 저장소의 예외가 보안·결제·데이터·릴리스 실행 변경을 제외하지 않는다.
- AC-3: 조건부 요청은 필수이며 리뷰 자체는 advisory, 승인 계산 제외다. 미해결 지적·CI·충돌·사람 승인 조건은 유지한다.
- AC-4: 한도 원인별 재시도 기준과 총 요청 2회 상한을 함께 적용한다.
- 검증: 계약 검증 테스트를 먼저 변경해 기존 계약에서 실패 확인 후 `npm test`, `npm run pack:check`, actionlint, 로컬 스킬 validator와 `scripts/validate.sh`, `git diff --check`를 실행한다.
- 제품 UI·빌드·마켓·프로덕션 변경이 없어 UI 3회 검수와 제품 E2E는 해당 없음. 실제 리뷰 요청이나 계정 기본값 변경도 이 작업의 실행 범위에 포함하지 않는다.

## 적용과 복구

중앙 계약 PR을 먼저 병합한 뒤 로컬 지침 PR을 병합하고 기본 checkout을 fast-forward한다. 관련 없는 사용자 변경과 클라이언트의 기존 스킬 링크를 보존한다. 문제 발견 시 해당 정책 커밋만 되돌리는 PR로 복구한다.

API 리뷰 깊이 지원은 공식 안내와 현재 공개 입력 스키마를 구분한다. 확인되지 않은 필드 이름을 명령에 넣지 않고, 개인 기본값 Lite 또는 PR별 선택과 결과의 `Review effort` 확인 방법을 안내한다.

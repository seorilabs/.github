# 로컬 모델 코드 리뷰로 봇 리뷰 대체

- 설계 ID·버전: `2026-10-21-local-model-review`, v1
- 상태: 승인된 대화 범위의 실행 명세
- 승인 근거: 2026-10-21 대화. 사용자가 "GitHub Copilot 쿼터가 생각보다 너무 적어서 상시로 로컬에서 한번 코드리뷰 하고 넘어가게 하는 것이 목적"이라 밝히고, 선택지에 (1) 교차 리뷰까지 전부 로컬 모델로 통일, (2) PR에 흔적을 남기지 않음, (3) 리뷰 실패 시 사유를 적고 자체 점검으로 진행을 골랐다.
- 원본: 이 문서의 최초 커밋. 연결 PR은 PR 본문에 기록한다.
- 대체하는 설계: [2026-10-12 리뷰 기본값과 저장소 예외 v1](../2026-10-12-review-policy-lite/design.md)

## 목적과 근거

Copilot 코드 리뷰는 조직 좌석이 아니라 개인 Copilot Pro 한도로 돌아 주간 한도에 자주 걸렸다. Codex 교차 리뷰도 ChatGPT 계정 한도를 쓴다. 로컬 MiniMax Code(`mcode`)는 무료 모델 `MiniMax-M3.1-Flash`로 돌릴 수 있고, 2026-10-20 실측에서 19줄 문서 변경을 3분 22초에 리뷰하며 다른 저장소의 정본까지 대조해 실제 결함 2건을 찾았다. 2026-10-21 실측에서는 60줄 셸 스크립트 변경을 6분에 리뷰해 실제 결함 1건(P1)과 타당한 개선 3건(P2)을 찾았다.

## 범위와 결정

| 변경 | 리뷰 |
|---|---|
| 문서·주석·번역·에셋·자동 생성물·릴리스 문구와 버전 메타데이터만 변경 | 생략 |
| 모든 저장소의 코드·설정 로직 변경(보안·결제·데이터·릴리스 실행·500줄 이상 포함) | Ready 전에 로컬 모델 리뷰 1회 |
| 리뷰 실행 실패·한도 소진 | 한 번 다시 실행, 그래도 안 되면 PR 본문에 원인 한 줄과 자체 점검으로 진행 |

- 단계는 `local-model-review`와 `required-checks`만 남긴다. Copilot `assisted-review`, Codex·Claude `cross-model-review`, Copilot Balanced 대체, 세 저장소 예외, 보안 민감 변경의 교차 리뷰 불가 사람 승인 조건을 없앤다.
- 리뷰어는 MiniMax Code를 작성 agent의 로컬에서 읽기 전용 지시로 실행한다. 작성 agent가 `origin/main...HEAD` diff를 만들어 파일로 넘긴다. 실행 전후 작업 트리 내용 지문(추적 파일 diff와 미추적 파일 해시)이 같은지 확인하고, 다르면 되돌린 뒤 한 번만 다시 실행한다.
- 리뷰 출력은 PR에 올리지 않는다. 실패 시나리오가 있는 지적만 고치고 나머지는 답하지 않고 버린다. 리뷰어의 심각도 표기만으로 수용하지 않는다. 이 규칙은 작은 모델의 오탐으로 턴이 길어지는 것을 막기 위한 것이다.
- 회차는 최대 2회다. 2회차는 수용한 수정이 새 로직을 만들었거나 리뷰 뒤에 커밋이 더 생겼을 때, 1회차 출력과 처리 결과, 리뷰한 SHA 이후 diff만 넘긴다. 실패 재실행은 회차당 한 번이다.
- 개발 워크플로 계약의 개별 승인 항목 `security-change-without-cross-review`를 문서와 함께 삭제한다.
- 병합 gate는 Seori thread 해결, 수용한 로컬 지적 수정 완료, required check 통과, 조건부 사람 승인이다.
- 실행 명령과 프롬프트는 `~/.agent`의 `seori-pr-workflow` 스킬 `scripts/local-review.sh`가 보유한다. 중앙 계약은 공급자·도구·모델·입력·읽기 전용·결과 미게시만 고정한다.

## 인수조건과 검증

- AC-1: 중앙 계약에 Copilot·Codex 리뷰 단계와 저장소 예외가 없고, 로컬 모델 리뷰 단계가 `optional: false`, `resultPostedToPr: false`, `readOnly: true`, `beforePullRequestReady: true`다.
- AC-2: 실패 처리가 한 번 재실행, 한도 소진 자동 재실행 금지, 사유 기록 후 자체 점검 진행, 다른 공급자 대체 금지다.
- AC-3: 지적 수용 기준은 실패 시나리오이며, 거부한 지적은 답하지 않는다. 회차 상한 2회를 유지한다.
- AC-4: CONTRIBUTING, 자율 이슈 루틴, 프로젝트 운영, 기여 계약, 개발 워크플로 문서가 같은 규칙을 가리킨다.
- 검증: 계약 테스트를 먼저 바꿔 기존 계약에서 실패를 확인한 뒤 `node --test`, `npm run pack:check`, `git diff --check`를 실행한다. 리뷰 스크립트는 `~/.agent` 변경분으로 1회차·2회차를 실측한다.
- 제품 UI·빌드·마켓·프로덕션 변경이 없어 UI 검수와 제품 E2E는 해당 없음. GitHub 개인 설정의 Copilot 자동 리뷰 해제는 사용자가 직접 한다.

## 적용과 복구

중앙 계약 PR을 먼저 병합한 뒤 `~/.agent` 지침·스킬 PR을 병합한다. 문제가 생기면 두 PR을 되돌리는 PR로 복구한다. 이미 열린 PR의 과거 Copilot·Codex 리뷰 thread는 기존 방식대로 답하고 Resolve한다.

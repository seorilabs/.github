# 게임의 첫 학습과 UI 입력 검수

모든 Seorilabs 게임에서 플레이어가 첫 행동을 이해하고, 화면의 목록과 버튼을 기대한 대로 조작할 수 있는지 확인한다. 세계관·아트 방향·규칙은 각 게임의 기획 원장이 소유한다. 이 문서는 표현과 검수 방법의 공통 기준이다.

## 플레이어에게 보여 주는 순서

1. 첫 화면에서 목표, 지금 할 행동, 행동에 드는 비용과 바로 나타나는 결과를 실제 플레이 물체로 보여 준다. 가능한 경우 카드·말·블록 같은 게임 속 요소와 숫자 변화를 사용한다. 그림만으로 뜻이 모호하면 짧은 말을 붙인다.
2. 조합·강화·자원 이름은 조건이나 용도를 먼저 드러낸다. 장식적인 세계관 이름은 남길 수 있지만, 중요한 행동을 그 이름만으로 설명하지 않는다. 예: `같은 숫자 2장`과 실제 카드 두 장. 긴 규칙은 필요한 시점의 도움말로 보낸다.
3. 화면의 설명을 줄일 때는 실제 플레이에서 필요한 정보가 사라지지 않게 한다. 목표·비용·효과·제한·실패 이유는 해당 행동 근처에 남긴다. 광고·구매·데이터 삭제에 관한 중요한 조건도 그림으로 숨기지 않는다.
4. 번역과 큰 글자에서 같은 의미와 행동 순서를 유지한다. 표시 문구만 바꿀 때 내부 식별자·저장 형식·계산 규칙을 함께 바꾸지 않는다. 생성된 문구에는 생성기와 실행 중 템플릿을 함께 적용한다.

## 화면과 입력을 끝까지 확인

- 첫 실행부터 첫 성공 또는 실패, 보상, 다음 선택까지 실제 상태 전이를 따라간다. 설명 화면 하나의 캡처나 컴파일 성공만으로 학습 가능성을 판정하지 않는다. 테스트용 상태를 주입했다면 명시한다.
- 작은·기준·긴 화면, 지원 언어, 큰 글자에서 실제 렌더를 본다. 버튼·팝업·가격·긴 효과 문구가 잘리거나 겹치지 않는지 확인한다. 필수 행동은 스크롤 가능한 내용과 함께 밀려 사라지지 않도록 확인한다.
- 스크롤 목록은 스크롤 막대를 잡지 않고 **내용 위에서** 드래그할 수 있어야 한다. 카드·버튼·장식 위에서 시작해도 움직여야 하며, 짧은 탭은 해당 항목을 한 번만 실행해야 한다. 버튼·장식·프레임을 포함한 모든 목록에 같은 공통 입력 계약을 적용하고 새 목록도 회귀 검사한다.
- 화면 캡처, 합성 입력, 데스크톱 조작, 실기기 터치를 서로 다른 증거로 기록한다. 실제 터치를 확인하지 않았다면 완료로 표시하지 않는다.

## QA 저장 격리

저장 초기화가 들어가는 전체 테스트와 화면 E2E는 플레이어·개발 저장과 분리된 실제 저장 경로에서만 실행한다. 설정 문자열만 확인하지 말고 **런타임이 해석한 경로를 초기화 전에 검사**한다. 기존 설정 파일을 덮어쓰거나, 테스트가 만들지 않은 저장을 정리 대상으로 삼지 않는다. 테스트 전후 개발 저장의 상태를 확인해 의도하지 않은 변경을 발견하면 즉시 기록하고 원인을 고친다.

Godot에서 `application/config/custom_user_dir_name`만 바꿔도 격리되지는 않는다. `application/config/use_custom_user_dir=true`를 함께 설정하고 `OS.get_user_data_dir()`가 전용 QA 폴더인지 확인한다. 모든 테스트 진입점에 이 확인을 적용한다.

## 검수 기록

기준 코드와 시안, 실제 렌더·진행 상태·화면 크기, 입력 결과, 수정 전후 차이, 미검증 항목을 남긴다. 불변 규칙은 공통 UI 구성요소와 회귀 검사에 넣고, 특정 게임의 용어·그림·경제 값은 그 게임의 원장에 남긴다. 배포·실기기 검증은 PR의 데스크톱 E2E와 별도 단계다.

이 기준은 Bloomhand의 [그림 중심 학습 변경](https://github.com/seorilabs/bloomhand/pull/12)과 [게임 전체 스크롤 수정](https://github.com/seorilabs/bloomhand/pull/9)에서 확인한 재발 원인을 바탕으로 한다. 당시 QA 저장 이름만 바꾼 초기 검증에서 데스크톱 개발 저장이 초기화되어, 실제 경로 확인을 필수로 삼았다.
